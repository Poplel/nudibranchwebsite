Guide

From nothing to a working library, in the order you'll actually do it.

Before you start. Nudibranch is a companion to Jellyfin, not a replacement for it. Jellyfin holds and serves the music; Nudibranch finds it, tags it, imports it, and gives you a player and an app on top. You'll want Jellyfin running first.

What you need

  • A machine that can run Docker and Docker Compose — a NAS, a home server, a VPS.
  • A Jellyfin server with a music library, and an admin API key for it.
  • Somewhere to keep the files: Nudibranch wants its own volumes for the library, staging, downloads, trash, backups and podcasts.
  • Optional: a slskd instance, if you want Nudibranch to fetch things for you.
  • Optional: an iPhone, iPad or Mac for the app.

Setting up the server

  1. Get the code

    Clone the repository onto the machine that will run it.

    git clone https://github.com/Poplel/Nudibranch.git
cd Nudibranch

  2. Write your .env

    Copy .env.example and fill it in. The settings that matter on day one are the public URL, the Jellyfin URL and API key, the first admin PIN, and the API key placeholder — change both of those before the server is reachable from anywhere but your own network.

    cp .env.example .env
$EDITOR .env

    slskd, Spotify, AcoustID and push settings can wait; add them when you want the features they unlock.

  3. Bring it up

    docker compose up -d

    That starts the API, the background worker and the web frontend. The worker and the API share one SQLite database and the same file volumes, so they need to be pointed at the same paths.

  4. Sign in and lock it down

    Open the public URL, sign in as the first admin using the PIN you set, and immediately change the password and rotate the pre-seeded API key. If the server is going to be reachable from the internet, put it behind HTTPS — a reverse proxy with a certificate, or a tunnel.

  5. Point it at Jellyfin

    Check the integration settings resolve: Nudibranch should be able to reach Jellyfin, and Jellyfin's music library should point at the same folder Nudibranch imports into. Run a scan from the Tools menu to confirm the round trip works.

Connecting the app

  1. Enter your server address

    The app asks for the address of your server — the same URL you use in a browser. It talks to that and nothing else.

  2. Sign in

    Use your Nudibranch username and password. The app stores a session token in the iOS Keychain and names the session after your device, so you can see and revoke it later under Settings → Sessions.

  3. Sync and download

    The library's metadata syncs down and is cached, so browsing works offline. Anything you want to hear offline needs an explicit download — tap the download control on a track, album or playlist.

  4. Turn on notifications, if you want them

    Notifications tell you when a download finishes, a wishlist item is matched, a podcast episode lands, or something needs approving. See the privacy policy for exactly what the push relay handles.

The day-to-day workflow

Almost everything that changes your library goes through the same shape: something is proposed, you review it, and it happens once approved.

You want to…WhereWhat happens
Add music you don't own Discover → Wishlist The request becomes a proposal; approving it queues a download, which imports itself when it lands.
Import files you already have Import (server/web only) Files in staging are read, matched against MusicBrainz and proposed as an import batch.
Fix tags, covers or duplicates Library → edit, or Tools Edits and maintenance tools stage their changes as proposals rather than rewriting files behind your back.
See what the server is doing Task Queue and Activity Background tasks, their progress and the application log.
Make something happen on a schedule Automations A trigger (time, interval, event, webhook or Shortcut), an action, and an optional notification.

Adding other people

Users get permissions per flow — library, discover, imports, approvals, playlists, activity, tools, automations, users. Admins bypass all of them. The practical version: give a housemate library:view and discover and they can listen and ask for things, without being able to reorganise the library or approve their own downloads. Grant wishlist:approve_all only to people you're happy having the last word.
